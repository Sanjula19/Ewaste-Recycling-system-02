## 4. Found four things that will block me

These came out of comparing the report's spec against what `backend/routers/iot.py`
actually does today. **None of these are fixed yet** — they're identified, not done.

### Blocker 1 — the ingest response is far too big for an ESP32 (backend)
`POST /api/iot/ingest` returns the whole `ForecastResponse`, which embeds `forecast_90d` —
90 data points × 7 float fields, tens of KB of JSON. The ESP32 only needs "SELL" or "HOLD".
→ Add a compact device response (e.g. `?compact=true`) returning just decision + actuator commands.

### Blocker 2 — the bin-full lockout isn't enforced (backend)
Report §6.2 says the backend rejects further ingestion until the lockout is explicitly
cleared. In reality `/ingest` never reads `_bin_state`, and nothing can clear a lockout.
→ Gate `/ingest` with `423 Locked`, and add a clear endpoint for the dashboard to call after dispatch.

### Blocker 3 — colour alone can't identify six metals (scope)
`_classify_by_color()` only handles reddish copper and bright-neutral aluminium, then 422s.
That's the honest answer — 3 channels can't separate steel/nickel/zinc, and PVC is any colour.
→ Send `known_material` from an operator selection. Use Clear/Lux only as the "item arrived" trigger.

### Blocker 4 — two servos will brown out the ESP32 (electrical)
MG996R stall ≈ 2.5 A, SG90 ≈ 700 mA, USB gives 500 mA. Powering them from the board resets
the ESP32 every time the crusher moves — and it looks exactly like a firmware crash.
→ Separate 5–6 V / 3 A supply, grounds tied to the ESP32, 1000 µF bulk cap on the servo rail.

### Smaller gotchas noted
- **HC-SR04 Echo outputs 5 V** into a 3.3 V pin → needs a divider (1 kΩ + 2 kΩ) on GPIO 18.
- **GPIO 12 is a strapping pin** — must read LOW at boot. If the board won't start with the
  gate servo attached, this is why.
- `tcs.getRGB()` already returns 0–255, which matches the `ColorReading` schema. Don't send raw 16-bit.
- `weight_kg` is validated `> 0` — never POST a zero reading or it 422s.
- Backend must run with `--host 0.0.0.0`, or the ESP32 can't reach it across the LAN.
